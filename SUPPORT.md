# Support & Community Help

Welcome to the `@OxDurgeshxO` developer ecosystem. This document explains how to report bugs, request assistance, ask architectural questions, and responsibly report security vulnerabilities.

---

## 1. Where to Get Help

| Question / Need | Recommended Channel | Response SLA |
|---|---|---|
| **Bug Reports & Issues** | [GitHub Issues with Bug Template](https://github.com/OxDurgeshxO/.github/issues/new?template=bug_report.yml) | 2–3 business days |
| **Feature Requests & Ideas** | [GitHub Discussions / Feature Request Template](https://github.com/OxDurgeshxO/.github/issues/new?template=feature_request.yml) | Weekly triage |
| **General Architecture Q&A** | [GitHub Discussions](https://github.com/OxDurgeshxO/.github/discussions) | Community-driven |
| **Security Vulnerabilities** | Private Security Advisory or Email (see below) | < 24 hours |

---

## 2. Reporting Bugs Effectively

Before opening a bug report:
1. Search existing issues and discussions to see if the issue is already reported or solved.
2. Check the relevant `docs/` or `README.md` for troubleshooting steps.
3. Fill out the structured [Bug Report Template](https://github.com/OxDurgeshxO/.github/issues/new?template=bug_report.yml), including:
   - Reproduction steps
   - Expected vs. actual behavior
   - Exact runtime/browser environment
   - Minimal terminal logs or stack traces

---

## 3. Security Reports (Responsible Disclosure)

**DO NOT report security vulnerabilities in public GitHub issues.**

Please refer to [SECURITY.md](./SECURITY.md) for full instructions:
- Use [GitHub Security Advisories](https://github.com/OxDurgeshxO/.github/security/advisories/new) to submit reports privately.
- Or email security reports directly to `durgeshduttsinha@gmail.com` with the subject `[SECURITY VULNERABILITY]: <Repo Name>`.
- We acknowledge reports within 24 hours and provide regular updates until a patched release is published.
